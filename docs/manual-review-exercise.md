# Small supervisor-review exercise

After the technical run, generate the 15 individual case worksheets using the [approved experiment instructions](live-evaluation.md). The mock condition uses the archived bounded mock. Live trials use repetition one. Each local worksheet has space for personal responses.

This worksheet is for the project owner to complete personally after reference review and after the corresponding candidate outputs are available. It contains **no participant results**. Do not begin live-condition trials using mock output as a substitute.

## Consistent task

For each S1–S5 case, inspect the same synthetic task, blocker, sources, approved decision (if any), and fixed-time flags. In the manual condition, hide all candidate output. In the mock condition, show the deterministic candidate. In the live condition, show only the actual recorded live candidate with its provider/model identity. Keep original sources available in every condition.

Start your own timer when the case is visible and stop when you have written the answers below. Record navigation steps using one definition throughout: each click that opens a source/history section or changes the displayed view counts as one step; typing does not. Do not record or replay an actual operational state transition during this exercise.

Answer these questions without opening the model prompt:

1. What is the recorded workflow state and material status, and which source supports each material observation?
2. What remains missing, UNKNOWN or conflicting?
3. What owner and next action have actually been approved, if any?
4. What question should the human reviewer clarify next?
5. Did the candidate omit evidence, introduce an unsupported claim, or imply authority it does not have?
6. For candidate conditions, would you APPROVE the candidate information, CORRECT it, REJECT it, or leave it UNRESOLVED? Explain corrections and cite supporting sources. This is not operational approval.

Rate usefulness: **1** hinders review; **2** mostly unhelpful; **3** neutral/mixed; **4** helps identify relevant evidence; **5** substantially helps without hiding uncertainty. For manual review, rate the usefulness of the structured case display. Record actual elapsed seconds and a short rationale; leave unknown measurements blank.

Repeated exposure still creates learning effects; rotating order reduces but does not remove them. ## Interpretation

Report the raw counts, medians and matched-case differences without claiming a causal improvement. A single project-owner reviewer cannot establish general usability or real staffing productivity. Differences can reflect practice, case order, familiarity with the code or expectations. If possible in later authorized work, use another reviewer and independently prepared equivalent case variants. That is a limitation and suggestion, not a claim that those participants or variants were already evaluated.

Do not change the acceptance thresholds after seeing outputs to obtain a passing result. Preserve failed or rejected trial outcomes. Safety violations fail their case even if the output was rated useful or reviewed quickly.
